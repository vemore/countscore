# `ASSET_REQUIREMENTS.md` still asks the reader to pick a brand colour and an icon concept

- **Noted:** 2026-09-20 — while deleting the two purple brand guides (docs/brand-guides)
- **Theme:** docs
- **Area:** docs
- **Blocks release:** no

`store_listing/ASSET_REQUIREMENTS.md` is the last survivor of the November 2025 asset
documents, and it still writes as if nothing were decided:

- `:78` — "Primary: Material Design colors (consider blue, green, or purple)"
- `:82-95` — "**Icon Concepts** (choose one): Scorecard Design / Game Elements / …"
- `:221` — the feature graphic's "Background: Gradient (purple to blue)"
- `:454`, `:460` — a colour-psychology table ending in "**For CountScore**: Consider blue
  (trust), green (positive), or purple (quality)"

All four are false today: the palette is settled in `lib/utils/app_theme.dart` (teal
`#0E8F88`, gold `#F2B705`, ink `#0E1716`), the icon is *generated* from `design/icon/`
(`.llmwiki/Release.md` §Icons) and the feature graphic is generated by
`scripts/generate_feature_graphic.py` in that teal. `grep -rn 673AB7` finds nothing here,
which is why docs/brand-guides left the file alone — it is the same trap in words rather
than in hex.

**Fix:** cut the file down to what it is useful for — Play's image specifications
(dimensions, formats, alpha, size limits), which nothing else states in one place — and
replace every "choose a colour" and "choose a concept" section with a pointer to
`lib/utils/app_theme.dart` and `.llmwiki/Release.md` §Icons. It should end up about the
length of the limits table in `store_listing/README.md`, not 460 lines.

**Acceptance:**
- `grep -rni "consider .*purple\|Icon Concepts" store_listing/` returns nothing.
- `ASSET_REQUIREMENTS.md` states no hex code of its own; it points at `app_theme.dart`.
- The Play image limits it carries still match the table in `.llmwiki/StoreListing.md`.
